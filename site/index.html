Most CVEs are not about you. A few are.

You run a firewall, a VPN, a NAS, a few self-hosted apps. Nobody's job is to read advisories for them. unpatched does it every morning, against the versions you actually run, and opens an issue only when one of them is affected.

The issue says what to install, and how urgent it is — judged by whether attackers are using the bug, not by its CVSS score.

Set it up in a private repository or read the guide

1,792 vulnerabilities are being exploited right now, according to CISA's KEV catalog this morning.

34,326 vulnerabilities in today's database touch the 71 products unpatched knows by name. Packages (Debian, Alpine, PyPI, npm and more) are looked up in OSV.

Your list of what you run never leaves your repository.

What it decides, and how

Each vulnerability is matched against your exact version, using the vendor's own version scheme — a FortiOS build, an Ivanti 22.7R2.5, a Debian 3.0.11-1~deb12u1. Every source is read on its own: the CVE record, NVD, OSV. One specific "affected" is enough. "Not affected" needs a source that actually has version ranges; when the data is missing or contradicts itself, the answer is unknown, with the reason.

Then it asks how soon you should act. Fix today means the bug is in CISA's Known Exploited list, or CISA says exploitation is active, or there is public exploit code and the thing faces the internet. This week means likely to be exploited soon (EPSS), critical, or serious and exposed. Software past its end of life gets its own line. Everything else is counted and kept out of your way.

Setup is two files

Put them in a private repository. The workflow runs every morning and needs no token of your own. unpatched init --github writes both for you.

unpatched.yml
version: 1
stack:
  - product: fortios
    version: "7.2.5"
    exposure: internet
    name: Office firewall
  - product: nextcloud
    version: "29.0.3"
  - purl: pkg:deb/debian/openssl@3.0.11-1~deb12u1?distro=bookworm
.github/workflows/unpatched.yml
on:
  schedule: [{ cron: "17 6 * * *" }]
  workflow_dispatch:
permissions: { contents: read, issues: write }
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: amet13/unpatched@v3

It also runs as a command, in Docker, and as an MCP server, so you can ask an assistant is anything I run affected by the new Ivanti bug? and get an answer from your own list. See the command line and agents.

What it won't do

It does not scan your code or container images; OSV-Scanner, Trivy and Grype do that well. It does not list every CVE a vendor ever had. It does not guess: no model decides a verdict, and every finding names its sources. It needs no account, no API key and no server.
